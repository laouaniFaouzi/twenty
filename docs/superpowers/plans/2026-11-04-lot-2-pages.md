**Goal:** Ajouter à l'app Interfaze des pages libres en arborescence, éditées avec l'éditeur en blocs de Twenty, avec des modèles, un onglet Pages sur les fiches Projet, Société et Opportunité, et une page d'aide pour créer une base de données.

**Tech Stack:** TypeScript, React 19 (composants d'app), `twenty-sdk` et `twenty-client-sdk` 2.38.0, Vitest 4, Playwright 1.60.0 (préinstallé, Chromium dans `/opt/pw-browsers/chromium`).

## Périmètre et écarts décidés

- **« Nouvelle page depuis un modèle »** (§7.4) est un **bouton**, présent dans la page « Pages » et dans l'onglet « Pages » des fiches Projet, Société et Opportunité. Ce n'est pas une entrée du menu de commandes, parce que le contexte d'exécution d'un composant donne l'identifiant de la fiche ouverte mais pas son objet. Or un projet partage l'identifiant de son opportunité depuis le lot 1.
- **Suppression d'une page** (§7.1) : la corbeille de Twenty ne déclenche pas `onDelete`. Une fonction logique rattache donc les sous-pages de la page supprimée à la parente de celle-ci : elles « remontent d'un niveau » exactement.
- **Sous-pages d'un modèle** : elles gardent `isTemplate` à faux. L'arbre les range sous leur modèle, dans la section « Modèles », et ne les montre jamais dans l'arborescence principale.

### Task 2: Arbre des pages et ordre des pages sœurs

**Files:**
- Create: `src/utils/page-tree.ts`
- Test: `src/utils/__tests__/page-tree.test.ts`

**Interfaces:**
- Produces :
  - `type PageSummary = { id: string; title: string | null; icon: string | null; position: number | null; parentPageId: string | null; isTemplate: boolean }` ;
  - `type PageTreeNode = PageSummary & { children: PageTreeNode[] }` ;
  - `buildPageTree(pages: PageSummary[]): { roots: PageTreeNode[]; templates: PageTreeNode[] }` ;
  - `orderSiblings<TPage extends { title: string | null; position: number | null }>(pages: TPage[]): TPage[]` ;
  - `computeSiblingReorder(siblings: PageSummary[], pageId: string, direction: 'up' | 'down'): { id: string; position: number }[]` ;
  - `nextChildPosition(pages: PageSummary[], parentPageId: string | null): number`.

- [ ] **Step 1: Écrire les tests qui échouent**

- **`orderSiblings`** : trie par `position` croissante (`null` en dernier), puis par titre (`localeCompare` en français, titre `null` traité comme « Sans titre »).
- **`buildPageTree`** :
  - les pages sans parente et sans `isTemplate` sont dans `roots`, et les modèles sans parente dans `templates` ;
  - les enfants sont triés avec `orderSiblings` ;
  - une page dont la parente est absente de la liste (supprimée) est une racine ;
  - les descendants d'un modèle restent sous ce modèle et n'apparaissent jamais dans `roots` ;
  - **cycle** : avec A → parente B et B → parente A, A et B apparaissent toutes deux à la racine. Chaque page apparaît exactement une fois dans tout l'arbre, et la fonction termine (Review Focus 1).
- **`computeSiblingReorder`** :
  - avec trois pages sœurs aux positions 0, 1 et 2, monter la troisième donne `[{ id: troisième, position: 1 }, { id: deuxième, position: 2 }]` ;
  - monter la première ou descendre la dernière donne `[]` ;
  - avec trois pages sœurs toutes en position `0` (ordre par titre A, B, C), descendre A renumérote dans l'ordre affiché puis échange. Le résultat contient seulement les positions qui changent, et l'ordre obtenu est B, A, C (Review Focus 5).
- **`nextChildPosition`** : 0 sans page sœur, sinon la position maximale + 1. Les positions `null` comptent pour 0. Les modèles comptent seulement parmi les modèles : `nextChildPosition` reçoit la liste déjà filtrée par l'appelant.

- [ ] **Step 2: Vérifier l'échec**. Run: `yarn test:unit src/utils/__tests__/page-tree.test.ts`. Expected: FAIL.

- [ ] **Step 3: Implémenter** dans `src/utils/page-tree.ts`.

Algorithme de `buildPageTree` :
1. Indexer les pages par identifiant.
2. Pour chaque page, remonter ses parentes en mémorisant les pages vues. Si la chaîne revient sur une page déjà vue, la page fait partie d'un cycle : elle est traitée comme une racine.
3. Construire les enfants à partir des parentes valides.
4. Répartir les racines entre `roots` et `templates` selon `isTemplate`.
